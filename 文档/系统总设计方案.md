# 《道》系统总设计方案

更新时间：2026-05-12

## 1. 文档目的

本文档根据更新后的 `文档/游戏介绍.md` 重新整理《道》的系统总设计，目标是把项目从“可运行开放世界原型”推进到“以世界规律、征兆、感知、自我找寻和高质量程序化表现为核心的可持续游戏架构”。

本文档同时记录：

1. 更新后的游戏需求理解。
2. 当前项目已经具备的系统能力。
3. 与新游戏介绍不符合或覆盖不足的部分。
4. 未来系统总架构。
5. 阶段开发路线与任务清单拆分依据。
6. 面向 3A 画面追求的程序化资产、材质、天气、地标和展示验收路线。

## 2. 核心理解

《道》不是以任务、数值、刷取和物品驱动的传统开放世界。它的核心体验是：玩家进入一个有规律的自然世界，不被任务面板命令，却能通过环境、人物、动物、天气、梦境、预兆和主动“感知”逐渐理解自己的方向。过程本身就是宝藏。

系统设计必须服务以下原则：

1. 世界先于剧情。剧情不是硬塞给玩家的任务链，而是世界规律、玩家意愿和征兆反馈共同形成的旅程。
2. 征兆替代任务指令。游戏可以暗示、记录、回应、加强和减弱，但不能把玩家变成执行清单的人。
3. 感知是主动理解世界的能力。玩家长期停留、注视、接近、对话、尝试或迷失都会形成意愿；意愿足够时，感知会让预兆更清晰。
4. 记事本替代任务栏。记事本记录经历、对话、梦境、观察和玩家自己的笔记，不显示“去某地完成某事”的待办式目标。
5. 地图必须有吸引力。每张大地图都要有标志性景观和标志性环境，例如沙暴中的巨大金字塔、带雾的河流、高耸山脉、远海小岛。
6. 多地图之间要通过自然边界过渡。河流、迷雾、山脉、海洋、渡口、港口、洞穴和能力门槛承担地图切换，而不是直接把所有地图摊开让玩家看见。
7. 自然世界要有运行规律。生物群系、天气、昼夜、季节、植物生长、动物觅食迁徙、人物劳作和行为树，都应逐步成为可模拟系统。
8. 程序化生成优先。由于缺少美术资源，地形、材质、地点、景观、天气、散布物和大部分视觉符号都要优先用代码生成。
9. AI 个性化历险是上层增强，不是底层依赖。必须先有确定性、可测试、可回放的旅程导演和世界规律，再接入 AI。
10. 第一人称和第三人称都必须支持。第一人称强化沉浸，第三人称强化角色存在感、旅行感和动作表现。
11. 画面表现不是装饰，而是征兆和世界规律能否被玩家相信的前提。没有美丽、可信、有尺度的世界，玩家不会愿意停留，也不会愿意追寻。
12. 程序化资产不是临时占位生成器，而应成为《道》的“视觉语法”：每个资产都要有语义、材质、LOD、行为或征兆关系。

## 3. 当前项目状态

当前项目已经具备第一层技术底座、开篇旅程雏形和多个核心系统原型，不能再视为空工程。新的判断应从“是否有功能”转为“这些功能是否足够美、足够可信、足够符合《道》的精神”。

### 3.1 已完成能力

1. Rust + Bevy 工程结构，`core` 与 `game` 模块已分离。
2. 配置、日志、性能采样、错误处理、开发脚本和展示脚本已经建立。
3. 程序化高度场、湿度、温度、坡度、河流、侵蚀、沉积和基础群系已实现。
4. 大型开放世界分块流式加载、LOD、后台生成、缓存、碰撞代理和远景 impostor 已实现。
5. 程序化地表材质和基础散布物已实现。
6. 昼夜、太阳、月亮、星空、雾、晴天、薄雾、雨、暴风雨、雪、粒子和闪电已实现。
7. 第一人称移动、鼠标视角、跳跃、坡度限制、台阶抬升和地形接触已实现。
8. 主菜单、探索模式、展示模式、暂停、继续、重开、返回主菜单和退出生命周期已打通。
9. 程序化意义地点已实现第一版：古树、泉眼、山脊门、静水湾、石阵。
10. 旅程系统已实现第一版：旅程阶段、目标地点、征兆记录、轻交互、世界回应和回响记忆。
11. 征兆系统已实现方向、强度、目标地点、接近阶段和回应强度。
12. 村庄开篇已实现第一版：出生点、屋舍、羊圈、集市、水井、海边、羊、牧羊人、商人和轻交互。
13. 梦境、梦后回响、意愿、主动感知和感知记录已实现第一版。
14. 记事本、正式 HUD、开发 HUD、方位感、归路入口和分类浏览已实现第一版。
15. 多区域世界、自然边界、迷雾旧渡口、山口、港口和区域切换状态已实现第一版。
16. 沙漠、沙暴、金字塔远景、绿洲、残墙和古物占位已实现第一版。
17. 鸟群、鱼群、羊群、牧羊人、商人、占卜人日程和生态征兆已实现第一版。
18. 第一人称与第三人称视角切换、第三人称镜头避障和角色动画状态枚举已实现第一版。
19. 硬编码导演接口、结构化输入输出、建议校验和离线回退已实现第一版。
20. 展示模式已覆盖世界、环境、征兆、村庄、梦境、边界、沙漠地标、生态、第三人称和导演接口。

### 3.2 当前项目本质

当前项目是“开放世界规律与征兆旅程原型 + 开篇英雄之旅原型”，已经证明以下事情可行：

1. 没有任务面板，也可以通过征兆和地点形成方向感。
2. 程序化世界可以支持第一段可玩探索。
3. 村庄、梦境、意愿、感知、记事本、多区域边界和沙漠地标可以形成闭环。
4. 生态行为、NPC 传闻、天气和地标显现可以作为征兆载体。
5. 硬编码导演可以先承担 AI 个性化系统的协议验证。

但它还没有满足“3A 大作质量追求”和“程序化生成为主”的完整目标。当前最大短板不是规则系统缺席，而是视觉资产、材质层次、角色可辨识度、地表细节、体积氛围、地标巨构和画面验收管线仍偏原型化。大量实体仍是 `Cuboid`、`Capsule`、`Cylinder`、纯色材质和基础粒子，能表达功能，但不足以让玩家相信这是一个值得停留和追寻的世界。

## 4. 当前不符合与覆盖不足

以下是对照游戏介绍和当前代码后，下一阶段最需要解决的主要差距。早期功能骨架已经基本形成，新的主要矛盾是“系统能运行，但世界还不够美、不够可信、不够有程序化资产生产能力”。

### 4.1 3A 画面基准不足

游戏介绍明确要求“没有一个美丽的画面效果，是不会有人愿意玩的”。当前展示模式能验证功能，却还没有稳定的画面标尺：没有明确的村庄黎明、梦后海风、迷雾边界、沙暴金字塔等核心样张，也没有截图、构图、光照、地标可见性和 UI 遮挡验收标准。

需要新增：

1. 画面基准样张矩阵。
2. 展示镜头的固定构图、时间、天气和相机轨迹。
3. 视觉验收清单：地标可见、层次清楚、无穿插、无 UI 遮挡、无调试感。
4. 关键改动前后截图和性能对比流程。

### 4.2 程序化资产生产线缺失

当前村庄、地标、自然边界、动物和人物大多在各自系统里直接生成基础几何体。这样能快速验证功能，但无法支撑长期迭代：资产没有统一语义、LOD、材质族、碰撞、展示和征兆绑定规则。

需要新增：

1. `ProceduralAssetSpec`：资产类型、语义标签、种子、尺寸、材质族、LOD 策略。
2. `ProceduralAssetRegistry` / `ProceduralAssetFactory`：统一生成房屋、树、岩石、草、遗迹、动物、NPC、地标部件。
3. 近景网格、中景简化、远景 impostor 三档资产输出。
4. 资产与征兆、感知、记事本、导演接口的语义连接。
5. 稳定种子、错误日志和性能埋点。

### 4.3 地表材质与植被细节不足

当前地形已有高度、湿度、温度、河流、侵蚀和基础群系，但近景地表仍偏平，材质层次和植被细节不足。开放世界的美感需要草、灌木、碎石、沙纹、河岸、湿地、雪面等高频细节，而这些细节必须随距离和性能预算降级。

需要新增：

1. 分层地表材质：草甸、林地、旷野、山脊、沙丘、戈壁、绿洲、水岸。
2. 程序化纹理：草色噪声、碎石点、沙纹方向、湿岸边界、积雪变化。
3. 高频散布物：草簇、灌木、树桩、落叶、碎石、风蚀石、干灌木、遗迹残片。
4. 天气影响：雨后湿润、沙暴覆尘、雪线积雪、感知时局部风纹变化。
5. 近景网格、中景批处理、远景材质噪声的 LOD 体系。

### 4.4 村庄生活氛围仍偏占位

村庄开篇已实现，但屋舍、羊圈、集市、水井、海边和人物仍主要依赖简单几何。它现在能说明“这里是村庄”，但还不足以让玩家愿意停留，也不足以承载“出发地就是最终宝藏”的精神重量。

需要新增：

1. 模块化房屋：墙、屋顶、梁柱、门窗、烟囱、台阶和暖窗光。
2. 功能点细节：羊圈草垛和踩踏地、集市布棚和货箱、水井绳桶和湿地、海边浅滩和旧木桩。
3. 生活动势：炊烟、布棚摆动、羊群聚散、海雾和鸟群。
4. 梦境前后的村庄氛围差异：宁静、梦后微弱不安、村外风向改变。

### 4.5 生态角色可辨识度不足

生态系统已有羊、鸟、鱼、NPC 日程和征兆信号，但视觉仍是胶囊体、球体或简单剪影。玩家必须能一眼看懂“羊在不安”“鸟群朝远处飞”“商人带来传闻”“占卜人只在合适时刻出现”，否则生态征兆会变成调试状态而不是体验。

需要新增：

1. 程序化动物形体：羊的头、四肢、羊毛体积；鸟的翅膀剪影；鱼的闪动形体。
2. 基础程序化动画：吃草、抬头、受惊、拍翼、滑翔、转向。
3. NPC 轮廓差异：牧羊人、商人、占卜人的服饰、手持物和姿态。
4. 行为驱动表现：征兆增强时动物和 NPC 的动作自然变化。

### 4.6 地标巨构仍不够震撼

沙漠金字塔已具备远景和近景占位，但要承担“梦中宝藏”和“远方召唤”的核心意义，仅有大三角体还不够。它需要巨大尺度、沙暴显隐、近景可探索空间、绿洲废墟和地下古城入口等层次。

需要新增：

1. 金字塔阶梯、边缘磨损、入口阴影、半埋底座和残破石块。
2. 远景 silhouette、中景简化面、近景可探索结构三档 LOD。
3. 绿洲、残墙、风蚀石、地下古城入口等地标周边空间。
4. 梦境、感知、沙暴和长期意愿对地标显现的联动。

### 4.7 天气天空与体积氛围不足

当前已有昼夜、太阳、月亮、星空、雾、雨、风暴、雪和沙暴粒子，但天空、云、体积雾、风场和地表响应仍偏基础。天气必须成为世界规律和征兆的一部分，而不是简单循环播放。

需要新增：

1. 程序化云层、云带、星带和更丰富的昼夜天空。
2. 区域色彩基准：村庄暖、海雾冷、山口硬、沙漠金灰、梦境高对比。
3. 雾、雨、雪、沙的多层表现：近处粒子、远处幕墙、地表响应、天空变色。
4. 统一风场，供草、布、沙、烟、鸟群和征兆表现共用。

### 4.8 视觉质量与性能验收管线不足

项目已有日志、性能报告和展示模式，但还没有把视觉迭代纳入强约束流程。画面升级会增加大量网格、材质、粒子和实体，必须从一开始建立展示截图、性能 baseline、配置回退和质量门槛。

需要新增：

1. 展示场景矩阵：村庄黎明、梦后村外、迷雾边界、沙暴金字塔、绿洲废墟、夜空海边。
2. 截图输出目录、配置摘要、commit 记录和前后对比。
3. 所有重型视觉系统接入 `FramePerformance`。
4. 粒子密度、植被密度、细节距离、雾强度等配置化回退。
5. 平均帧耗时、p95、p99、超预算帧和瓶颈阶段的性能结论。

## 5. 总体系统架构

未来系统按“底层世界规律 -> 程序化资产与表现语法 -> 中层意愿与征兆 -> 上层旅程叙事 -> 展示与验收”的方式演进。

### 5.1 Core 层

负责配置、日志、错误、性能、测试辅助、自动化验证和开发工具。

设计要求：

1. 所有重型系统必须有配置入口。
2. 关键纯逻辑必须有单元测试。
3. 旅程、地图切换、AI 建议和感知触发都要写入日志，便于复盘。
4. 性能相关系统必须接入 `FramePerformance`。
5. 展示模式和自动退出验证必须持续可用。

### 5.2 World 层

负责地形、高度场、群系、水系、分块流式、区域边界、空间查询和地图切换底座。

未来需要从“单张连续地形”升级为“多区域世界”：

1. `WorldMap`：保留当前单区域采样能力。
2. `WorldRegion`：新增区域定义，包含区域类型、种子、地标、环境、危险、资源和边界。
3. `RegionGraph`：描述村庄、海边、沙漠、山后地图、远海小岛等区域之间的关系。
4. `TransitionGate`：自然边界，例如雾河、山口、港口、洞穴、海路。
5. `WorldStreaming`：按当前区域加载地形与地点，保留跨区域旅程状态。

2026-05-12 补充实现：`WorldMap` 已开始承担区域化采样职责，沙漠影响层会在基础高度场上叠加连续沙丘、戈壁平整度和绿洲湿度；区域切换时会清理当前地形分块、细节实体、远景 impostor、碰撞代理和流式队列，并保留旅程、梦境、记事本等全局状态。

### 5.3 Procedural Asset 层

新增统一程序化资产生产线，负责把“代码生成占位物”升级为可迭代的视觉语法。

职责：

1. `ProceduralAssetSpec` 描述资产类型、语义标签、种子、尺寸、材质族、LOD 策略和碰撞需求。
2. `ProceduralAssetRegistry` 统一登记房屋、树、岩石、草、遗迹、动物、NPC、地标部件和边界部件。
3. `ProceduralAssetFactory` 负责生成近景网格、中景简化体、远景 impostor 或材质噪声代理。
4. 资产根实体统一带语义组件，供征兆、感知、记事本、生态和导演查询。
5. 资产生成要可复现、可清理、可性能统计，避免各系统散落临时 `Cuboid` / `Capsule`。

第一批资产族：

1. 村庄建筑：屋舍、屋顶、门窗、烟囱、井、围栏、布棚、货箱。
2. 自然细节：草簇、灌木、树桩、碎石、风蚀石、沙纹、湿岸。
3. 生态角色：羊、鸟、鱼、牧羊人、商人、占卜人。
4. 地标部件：金字塔阶梯、残墙、入口、半埋石块、绿洲边缘、地下古城门。
5. 边界部件：雾河、山口石柱、港口木桩、海雾灯火。

### 5.4 Surface / Vegetation 层

新增地表材质与植被细节层，负责让地形近看有质感、远看有层次。

职责：

1. 按高度、坡度、湿度、温度、河流、侵蚀、沉积和区域 profile 混合地表材质。
2. 为草甸、林地、旷野、山脊、沙丘、戈壁、绿洲、水岸生成不同细节。
3. 使用近景网格、中景批处理、远景材质噪声三级 LOD。
4. 天气可以改变地表：雨后湿润、雪线积雪、沙暴覆尘、梦境风纹。
5. 植被和地表细节可以成为弱征兆载体，但不能形成硬性路线。

### 5.5 Landmark 层

新增区域级标志性景观系统。

职责：

1. 为每张地图生成至少一个核心地标。
2. 提供远景轮廓和近景可探索结构。
3. 绑定专属环境和征兆。
4. 支持梦境和记事本引用。

第一批地标建议：

1. 村庄海岬：出生地附近的海、牧场、集市、灯火。
2. 巨大金字塔：沙漠地图核心远景。
3. 迷雾河：区域边界和渡河门槛。
4. 山脊门：翻越山地的自然关口。
5. 远海小岛：后续探索目标。

2026-05-12 补充实现：沙漠金字塔地标除远景/近景轮廓外，已生成绿洲水面、残墙和古物占位，供梦境、征兆、记事本和后续哲学物品流程引用。

### 5.6 Environment 层

负责昼夜、天气、季节、天空、雾、风、粒子、环境光和区域专属环境。

设计要求：

1. 天气不能只是循环播放，要能被区域、地标、征兆、梦境和旅程阶段影响。
2. 沙漠需要沙尘暴，海边需要海雾和潮湿空气，山地需要云海和强风。
3. 环境变化可以是征兆的一部分，但不能总是强制指路。
4. 季节和植物生长先做低成本状态，再逐步扩展视觉。

2026-05-12 补充实现：沙暴关键参数已接入 `config/app.toml` 的 `[desert]` 段，包括能见度、粒子强度和风速，便于性能采样后调参。

未来扩展：

1. 建立统一风场资源，供草、布、烟、沙、鸟群和征兆共同读取。
2. 天空从纯色渐变升级为云层、云带、星带和区域色彩基准。
3. 雾、雨、雪、沙分成近处粒子、远处幕墙、地表响应和天空变色四层。
4. 梦境和感知只能短暂调制天气表现，不能破坏世界规律。

### 5.7 Places 层

负责小到中尺度的意义地点。

当前已有：古树、泉眼、山脊门、静水湾、石阵。

未来扩展：

1. 村庄地点：羊圈、井、集市、海边、老人屋、占卜帐篷。
2. 沙漠地点：绿洲、残墙、地下古城入口、风蚀石柱、废弃营地。
3. 边界地点：渡口、山口、灯塔、洞穴、旧路标。
4. 地点要有语义标签，供征兆、感知、记事本和 AI 导演查询。

### 5.8 Ecology 层

新增生态与人物行为层。

职责：

1. 动物生成、群体移动、觅食、迁徙、惊扰和回归。
2. NPC 日程、工作、休息、对话和简单关系。
3. 生态事件：鸟群迁飞、羊群走散、鱼群出没、商队经过。
4. 行为可以成为征兆载体，例如飞鸟方向、羊群不安、商人传闻。

初期不追求复杂仿真，优先做少量高辨识行为。

2026-05-12 补充实现：生态系统已按配置控制鸟群/鱼群数量，并通过状态更新间隔和视觉更新间隔分频，避免每帧重算全部行为。

表现要求：

1. 动物和人物必须从行为状态驱动姿态，而不是独立装饰循环。
2. 羊、鸟、鱼、牧羊人、商人、占卜人要有清楚轮廓和基础动画。
3. 生态征兆必须先表现为自然行为变化，再被感知系统放大。

### 5.9 Journey 层

负责长期旅程状态、阶段推进、梦境、玩家意愿和导演接口。

当前已有短旅程状态。未来拆分为：

1. `JourneyState`：保留短期旅程、当前阶段、记忆和回应。
2. `StoryArcState`：新增长期主线，如村庄、梦境、寻找出路、渡河、沙漠、金字塔。
3. `IntentState`：记录玩家行为体现出的意愿，如向海、向山、停留村庄、寻找商人、追随鸟群。
4. `DreamState`：管理梦境触发、梦境内容、醒后回响和反复出现。
5. `DirectorState`：选择下一批候选征兆、地点、NPC 或梦境，但不显示任务目标。

### 5.10 Omen / Sign 层

负责征兆生成、强度、方向、阶段、衰退、回归和表现触发。

未来规则：

1. 征兆来自世界规律，而不是凭空出现。
2. 征兆与玩家意愿相关，意愿越明确，征兆越清晰。
3. 玩家长期无视时，征兆逐渐消退。
4. 玩家重新寻找时，征兆逐渐回归。
5. 感知会临时提高征兆可读性。
6. 征兆表现包括光、风、鸟群、雾、沙暴间隙、星空、声音预留、NPC 话语和地标轮廓。

### 5.11 Perception 层

新增主动感知系统。

职责：

1. 接收玩家主动输入。
2. 判断是否有足够意愿、平静度或情境条件。
3. 请求征兆系统增强表现。
4. 记录感知结果到记事本。
5. 失败时给出自然反馈，例如风声散去、鸟群沉默，而不是 UI 报错。

### 5.12 Notebook 层

新增记事本系统，替代任务栏。

职责：

1. 自动记录梦境。
2. 自动记录重要对话。
3. 自动记录抵达地点和世界回应。
4. 自动记录玩家观察到的征兆。
5. 支持后续玩家手写笔记。
6. 支持按“梦境、人物、地点、征兆、旅程回响”浏览。

禁止：

1. 不显示待办任务。
2. 不显示任务完成百分比。
3. 不显示奖励清单。
4. 不把 AI 建议直接翻译成命令。

### 5.13 UI 层

负责主菜单、暂停、正式 HUD、开发 HUD、记事本、小地图、临时物品栏和设置。

设计要求：

1. 正式 HUD 默认极简。
2. 开发 HUD 可开关，显示坐标、共鸣、平静、距离等调试信息。
3. 小地图只帮助空间理解，不画任务路线。
4. 地点方向指引要像自然方位或记忆标记，不像任务箭头。
5. 快速移动只对已抵达、已理解且叙事允许的地点开放。
6. 物品栏默认不存在，只在造船、特殊哲学物品或临时流程中出现。

### 5.14 Camera / Player 层

负责第一人称、第三人称、移动、跳跃、交互和视角切换。

设计要求：

1. 第一人称继续作为沉浸探索主模式。
2. 第三人称要支持旅行、观察角色、过渡动画和展示模式。
3. 两种视角共享同一个玩家身体和交互状态。
4. 第三人称先用占位角色和程序化动画，不等待完整美术。

2026-05-12 补充实现：第三人称镜头距离、高度、侧向偏移、平滑和地面净空已配置化；角色占位具备站立、行走、奔跑、跳跃四类基础动画状态枚举，供后续视觉动画接入。

### 5.15 Interaction 层

负责轻交互、对话、临时物品和环境动作。

优先级：

1. 靠近、停留、注视、聆听。
2. 与 NPC 对话。
3. 与动物轻互动。
4. 读写记事本。
5. 造船、渡河、开门等地图边界动作。
6. 战斗暂不作为核心优先级。

### 5.16 AI Director 层

负责未来 AI 个性化历险接入。

接口原则：

1. AI 只提出候选，不直接控制世界。
2. 所有候选必须经过世界规则验证。
3. AI 失败时使用硬编码导演回退。
4. AI 输出要结构化，避免直接把大段文本塞进游戏逻辑。
5. 记录输入、输出、采纳结果和回退原因，便于调试。

### 5.17 Presentation / Visual QA 层

负责每个阶段的可重复展示、截图对比和性能验收。

要求：

1. 每个大系统必须有展示模式覆盖。
2. 展示不依赖随机碰撞，必须可重复播放。
3. 新增系统先进入展示模式，再接入正式探索。
4. 展示分组必须覆盖村庄黎明、梦后村外、迷雾边界、沙暴金字塔、绿洲废墟、夜空海边。
5. 视觉改动需要前后截图、配置摘要和性能 baseline。
6. 质量判断同时看截图、日志、性能报告和实际运行，不能只看终端是否通过。

## 6. 阶段开发路线

前一批任务已经把村庄、梦境、意愿、感知、记事本、多区域、沙漠地标、生态、第三人称和导演接口推进到第一版。下一阶段路线不再重复补功能，而是围绕“3A 方向的程序化表现”迭代。

### 阶段一：3A 画面基准与镜头表现

目标：先定义《道》到底要长成什么样，而不是继续盲目堆系统。

核心交付：

1. 村庄黎明、梦后海风、迷雾边界、沙暴金字塔四个核心样张。
2. 展示镜头固定时间、天气、相机和构图。
3. 截图检查清单和禁止项。
4. 第一人称与第三人称展示镜头。

### 阶段二：程序化资产生产线

目标：把散落的占位几何升级为统一资产语法。

核心交付：

1. `ProceduralAssetSpec`。
2. `ProceduralAssetRegistry` / `ProceduralAssetFactory`。
3. 材质族、语义标签、LOD 策略和根实体管理。
4. 房屋、围栏、草、石、羊、鸟、NPC、金字塔部件第一批资产。
5. 稳定种子、日志、测试和性能埋点。

### 阶段三：地表材质与植被细节

目标：让开放世界近看有质感，远看有层次。

核心交付：

1. 分层地表材质。
2. 程序化草、灌木、碎石、沙纹、湿岸、积雪。
3. 天气影响地表。
4. 细节 LOD 和批处理。
5. 近景地表展示镜头。

### 阶段四：村庄资产升级与生活氛围

目标：先建立正式环境资产锚点与氛围控制层，再让出生村庄成为玩家愿意停留、最终愿意回望的精神原点。

核心交付：

1. 房屋、羊圈、集市、水井、海边的正式资产锚点与替换路径。
2. 村庄氛围控制参数：时间段、风向、风强、湿度、海雾、生活密度。
3. 梦前宁静与梦后不安的统一环境状态。
4. 正式 VFX、材质和音频接口，而不是继续细修几何占位动效。
5. 村庄黎明展示镜头与审美验收样张。

### 阶段五：生态角色程序化表现

目标：先建立正式角色资产接入与替身体系，再让动物和人物成为可信居民和征兆载体。

核心交付：

1. 羊、鸟、鱼、牧羊人、商人、占卜人的正式资产锚点与替换路径。
2. 近景角色、中景简化角色、远景群体替身的 LOD 体系。
3. 行为状态到动画状态、VFX、音频提示的分层接口。
4. 生态征兆的正式视觉表达，而不是程序化玩具几何。
5. 可见距离、更新分频、替身切换和性能验证。

### 阶段六：地标巨构与沙漠奇观

目标：把金字塔升级为真正有吸引力的远方奇观。

核心交付：

1. 金字塔阶梯、磨损、入口、半埋底座和残石。
2. 远景、中景、近景三档 LOD。
3. 绿洲、残墙、风蚀石和地下古城入口。
4. 沙暴、梦境和感知显现联动。
5. 沙暴远景与近景废墟展示镜头。

### 阶段七：天气天空与体积氛围

目标：让天气和天空成为世界规律与征兆的一部分。

核心交付：

1. 云层、云带、星带和区域色彩基准。
2. 雾、雨、雪、沙的多层表现。
3. 统一风场。
4. 草、布、烟、沙、鸟群共享风向。
5. 天气表现性能对比。

### 阶段八：视觉展示与性能验收管线

目标：让画面迭代可展示、可截图、可回放、可性能对比。

核心交付：

1. 展示场景矩阵。
2. 截图输出目录、配置摘要和 commit 记录。
3. 性能 baseline 与 compare 流程。
4. 视觉质量回退配置。
5. 文档、截图、日志、性能报告共同验收。

## 7. 当前最高优先级

当前最高优先级不是继续扩大玩法范围，也不是马上接入外部 AI，而是把已经跑通的英雄之旅原型升级为玩家愿意相信的世界。优先级如下：

1. 3A 画面基准与镜头表现。
2. 程序化资产生产线。
3. 地表材质与植被细节。
4. 村庄资产升级与生活氛围。
5. 地标巨构与沙漠奇观。
6. 天气天空与体积氛围。
7. 生态角色程序化表现。
8. 视觉展示与性能验收管线。

这八项完成后，《道》才会从“功能上符合愿景的原型”进入“画面上开始有吸引力、资产上可以持续生长的开放世界原型”。

## 9. 结论

当前项目已经完成了有价值的功能原型：程序化世界、流式地形、环境视觉、第一/第三人称探索、村庄开篇、梦境、意愿、感知、记事本、多区域边界、生态、沙漠金字塔、导演接口和展示模式。它已经开始符合“从村庄出发，经由梦境、意愿、感知、征兆和自然边界，走向远方地标的英雄之旅”。

下一阶段必须围绕表现力收束：把占位几何升级为程序化资产，把纯色材质升级为分层材质，把动物和人物升级为可辨识角色，把金字塔升级为真正的远方奇观，并用展示截图和性能报告约束每次迭代。这样《道》的精髓才会落在玩家能亲眼相信的世界里：没有任务命令，只有世界运行、征兆显现和玩家自己的出发。
