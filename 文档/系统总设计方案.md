# 《道》系统总设计方案

更新时间：2026-05-12

## 1. 文档目的

本文档根据更新后的 `文档/游戏介绍.md` 重新整理《道》的系统总设计，目标是把项目从“可运行开放世界原型”推进到“以世界规律、征兆、感知和自我找寻为核心的可持续游戏架构”。

本文档同时记录：

1. 更新后的游戏需求理解。
2. 当前项目已经具备的系统能力。
3. 与新游戏介绍不符合或覆盖不足的部分。
4. 未来系统总架构。
5. 阶段开发路线与任务清单拆分依据。

## 2. 核心理解

《道》不是以任务、数值、刷取和物品驱动的传统开放世界。它的核心体验是：玩家进入一个有规律的自然世界，不被任务面板命令，却能通过环境、人物、动物、天气、梦境、预兆和主动“感知”逐渐理解自己的方向。过程本身就是宝藏。

系统设计必须服务以下原则：

1. 世界先于剧情。剧情不是硬塞给玩家的任务链，而是世界规律、玩家意愿和征兆反馈共同形成的旅程。
2. 征兆替代任务指令。游戏可以暗示、记录、回应、加强和减弱，但不能把玩家变成执行清单的人。
3. 感知是主动理解世界的能力。玩家长期停留、注视、接近、对话、尝试或迷失都会形成意愿；意愿足够时，感知会让预兆更清晰。
4. 记事本替代任务栏。记事本记录经历、对话、梦境、观察和玩家自己的笔记，不显示“去某地完成某事”的待办式目标。
5. 地图必须有吸引力。每张大地图都要有标志性景观和标志性环境，例如沙暴中的巨大金字塔、带雾的河流、高耸山脉、远海小岛。
6. 多地图之间要通过自然边界过渡。河流、迷雾、山脉、海洋、渡口、港口、洞穴和能力门槛承担地图切换，而不是直接把所有地图摊开让玩家看见。
7. 自然世界要有运行规律。生物群系、天气、昼夜、季节、植物生长、动物觅食迁徙、人物劳作和行为树，都应逐步成为可模拟系统。
8. 程序化生成优先。由于缺少美术资源，地形、材质、地点、景观、天气、散布物和大部分视觉符号都要优先用代码生成。
9. AI 个性化历险是上层增强，不是底层依赖。必须先有确定性、可测试、可回放的旅程导演和世界规律，再接入 AI。
10. 第一人称和第三人称都必须支持。第一人称强化沉浸，第三人称强化角色存在感、旅行感和动作表现。

## 3. 当前项目状态

当前项目已经具备第一层技术底座和一个短小旅程闭环，不能再视为空工程。

### 3.1 已完成能力

1. Rust + Bevy 工程结构，`core` 与 `game` 模块已分离。
2. 配置、日志、性能采样、错误处理、开发脚本和展示脚本已经建立。
3. 程序化高度场、湿度、温度、坡度、河流、侵蚀、沉积和基础群系已实现。
4. 大型开放世界分块流式加载、LOD、后台生成、缓存、碰撞代理和远景 impostor 已实现。
5. 程序化地表材质和基础散布物已实现。
6. 昼夜、太阳、月亮、星空、雾、晴天、薄雾、雨、暴风雨、雪、粒子和闪电已实现。
7. 第一人称移动、鼠标视角、跳跃、坡度限制、台阶抬升和地形接触已实现。
8. 主菜单、探索模式、展示模式、暂停、继续、重开、返回主菜单和退出生命周期已打通。
9. 程序化意义地点已实现第一版：古树、泉眼、山脊门、静水湾、石阵。
10. 旅程系统已实现第一版：旅程阶段、目标地点、征兆记录、轻交互、世界回应和回响记忆。
11. 征兆系统已实现方向、强度、目标地点、接近阶段和回应强度。
12. 展示模式已覆盖世界、环境、征兆和第一段可玩旅程闭环。

### 3.2 当前项目本质

当前项目是“开放世界规律与征兆旅程原型”，已经证明以下事情可行：

1. 没有任务面板，也可以通过征兆和地点形成方向感。
2. 程序化世界可以支持第一段可玩探索。
3. 旅程状态、地点、征兆、环境和 UI 可以形成闭环。

但它还没有满足更新后游戏介绍中的完整目标，尤其缺少“村庄开篇、梦境、感知、记事本、多地图、标志性景观、生态人物行为和第三人称”。

## 4. 当前不符合与覆盖不足

以下是对照更新后游戏介绍后，当前系统存在的主要差距。

### 4.1 开篇体验不符合

游戏介绍要求玩家出生在美好宁静的村庄，有羊群、商人、牧羊人、大海，以及可以一直停留的生活空间。当前项目直接进入程序化野外，没有村庄、村民、羊群、商人、海边生活区，也没有“可以不出发”的日常体验。

需要新增：

1. 村庄地图或村庄区域生成。
2. 羊群、牧羊人、商人等第一批 NPC/动物。
3. 日常行为和轻交互。
4. 玩家停留数日后触发梦境的开篇节奏。

### 4.2 剧情推进方式覆盖不足

游戏介绍要求先按《炼金术士》式硬编码剧情推进：出生村庄、几天后梦见金字塔下的宝藏、预兆逐渐加强、如果长期不回应则消退、玩家重新努力后预兆回归。当前 `JourneyState` 只有短旅程闭环，没有“天数、梦境、内心宝藏、前往沙漠、预兆加强/消退/回归”的长期旅程结构。

需要新增：

1. 长期旅程主线状态。
2. 梦境系统。
3. 预兆随玩家意愿增强、衰退、回归的规则。
4. 从村庄走向第一张远方地图的剧情骨架。

### 4.3 感知系统缺失

游戏介绍明确提出主动技能“感知”：当玩家积累足够意愿后，可以发动感知，让预兆以更明显方式展现。当前项目只有被动征兆，没有意愿积累、感知输入、感知冷却、感知表现增强和感知失败反馈。

需要新增：

1. `IntentState` 或旅程意愿子系统。
2. 感知输入与状态。
3. 感知增强层：光、鸟群、风、雾、声音预留、远景轮廓强化。
4. 感知不能变成任务导航，只能让已有征兆更可理解。

### 4.4 记事本缺失

游戏介绍要求只有记事本作为帮助功能，可记录大小事情和过往对话。当前项目有暂停界面“回响”，但不是正式记事本，没有独立入口、分类、对话记录、梦境记录、地点记录和玩家笔记能力。

需要新增：

1. 记事本 UI 入口。
2. 自动记录：梦境、对话、地点、征兆、重要观察。
3. 手动记录预留：玩家笔记。
4. 与任务系统隔离，避免待办化。

### 4.5 UI 目标不完整

游戏介绍要求极简 UI，但同时小地图、地点方向指引、地点快速移动“可以有”，并强调非必要不显示持久物品栏。当前 HUD 仍偏开发调试面板，显示共鸣、平静、坐标和距离等数值。正式体验需要隐藏调试信息，建立可开关开发 HUD、正式 HUD、记事本、小地图和临时物品栏规则。

需要新增：

1. 开发 HUD 与正式 HUD 完全分离。
2. 小地图或方位感系统。
3. 地点方向指引的非任务化表达。
4. 快速移动规则：只对已理解、已抵达、符合叙事条件的地点开放。
5. 临时物品栏：只在特殊物品相关流程中出现。

### 4.6 多地图与自然边界缺失

游戏介绍要求世界由多张不同地图组成，并通过迷雾河流、高山、海洋、小岛、港口、造船、翻山等方式自然切换。当前项目只有一个大型连续地形，没有世界区域定义、地图边界、跨地图过渡、沙漠、海岛、山后地图，也没有“不要从一张地图直接看到另一张地图”的技术策略。

需要新增：

1. `WorldRegion` / `MapRegion` 架构。
2. 区域级种子、群系、天气、资源、危险和标志性景观。
3. 自然边界和过渡机制。
4. 远景遮挡、雾墙、山脉屏障、海面边界。
5. 地图切换时的流式卸载/加载和状态保留。

### 4.7 标志性景观和标志性环境不足

当前意义地点是小尺度地点，能支持短旅程，但游戏介绍要求每张地图至少有一个足够大、足够美或足够有意义的标志性景观。例如沙暴中千米外可见的巨大金字塔。当前缺少区域级地标、远距离轮廓、专属天气和地标吸引逻辑。

需要新增：

1. 区域地标系统。
2. 大尺度程序化几何体。
3. 地标远景 LOD / silhouette。
4. 地标专属环境，如沙暴、极光、海雾、山间云海。
5. 地标与征兆、梦境、记事本的语义绑定。

### 4.8 自然生态和人物行为不足

当前只有 `WandererPrototype` 漫游体，尚无动物、人物、行为树、迁徙、觅食、劳作、对话和村庄日程。游戏介绍明确需要自然规律、生物群系、生物和人物行为树。

需要新增：

1. 轻量行为树或效用 AI。
2. 动物群：羊、鸟、鱼或第一批自然动物。
3. NPC：牧羊人、商人、占卜人。
4. 日程系统：劳作、休息、交易、迁徙。
5. 生态表现与征兆联动：鸟群方向、动物异常、村民传闻。

### 4.9 第三人称缺失

当前只支持第一人称。游戏介绍要求第一人称和第三人称主视角游玩。第三人称不仅是镜头，还涉及角色模型占位、动画状态、碰撞同步、镜头避障和视角切换。

需要新增：

1. 视角模式状态。
2. 第三人称跟随镜头和碰撞避让。
3. 程序化或占位角色表现。
4. 第一/第三人称输入共享。
5. 展示模式覆盖两种视角。

### 4.10 AI 个性化接口仍为空

游戏介绍要求每个人的历险不同，AI 可以先硬编码但要留接口。当前系统已有确定性旅程导演雏形，但还没有清晰的 AI 适配边界、输入输出 schema、离线回退策略、内容安全边界和可回放日志。

需要新增：

1. `JourneyDirector` 接口抽象。
2. 硬编码导演与 AI 导演同一协议。
3. AI 建议只能影响候选，不直接破坏世界规则。
4. 对话、梦境、征兆文本和地点语义的生成边界。
5. 可回放记录与失败回退。

## 5. 总体系统架构

未来系统按“底层世界规律 -> 中层意愿与征兆 -> 上层旅程叙事 -> 表现与 UI”的方式演进。

### 5.1 Core 层

负责配置、日志、错误、性能、测试辅助、自动化验证和开发工具。

设计要求：

1. 所有重型系统必须有配置入口。
2. 关键纯逻辑必须有单元测试。
3. 旅程、地图切换、AI 建议和感知触发都要写入日志，便于复盘。
4. 性能相关系统必须接入 `FramePerformance`。
5. 展示模式和自动退出验证必须持续可用。

### 5.2 World 层

负责地形、高度场、群系、水系、分块流式、区域边界、空间查询和地图切换底座。

未来需要从“单张连续地形”升级为“多区域世界”：

1. `WorldMap`：保留当前单区域采样能力。
2. `WorldRegion`：新增区域定义，包含区域类型、种子、地标、环境、危险、资源和边界。
3. `RegionGraph`：描述村庄、海边、沙漠、山后地图、远海小岛等区域之间的关系。
4. `TransitionGate`：自然边界，例如雾河、山口、港口、洞穴、海路。
5. `WorldStreaming`：按当前区域加载地形与地点，保留跨区域旅程状态。

2026-05-12 补充实现：`WorldMap` 已开始承担区域化采样职责，沙漠影响层会在基础高度场上叠加连续沙丘、戈壁平整度和绿洲湿度；区域切换时会清理当前地形分块、细节实体、远景 impostor、碰撞代理和流式队列，并保留旅程、梦境、记事本等全局状态。

### 5.3 Landmark 层

新增区域级标志性景观系统。

职责：

1. 为每张地图生成至少一个核心地标。
2. 提供远景轮廓和近景可探索结构。
3. 绑定专属环境和征兆。
4. 支持梦境和记事本引用。

第一批地标建议：

1. 村庄海岬：出生地附近的海、牧场、集市、灯火。
2. 巨大金字塔：沙漠地图核心远景。
3. 迷雾河：区域边界和渡河门槛。
4. 山脊门：翻越山地的自然关口。
5. 远海小岛：后续探索目标。

2026-05-12 补充实现：沙漠金字塔地标除远景/近景轮廓外，已生成绿洲水面、残墙和古物占位，供梦境、征兆、记事本和后续哲学物品流程引用。

### 5.4 Environment 层

负责昼夜、天气、季节、天空、雾、风、粒子、环境光和区域专属环境。

设计要求：

1. 天气不能只是循环播放，要能被区域、地标、征兆、梦境和旅程阶段影响。
2. 沙漠需要沙尘暴，海边需要海雾和潮湿空气，山地需要云海和强风。
3. 环境变化可以是征兆的一部分，但不能总是强制指路。
4. 季节和植物生长先做低成本状态，再逐步扩展视觉。

2026-05-12 补充实现：沙暴关键参数已接入 `config/app.toml` 的 `[desert]` 段，包括能见度、粒子强度和风速，便于性能采样后调参。

### 5.5 Places 层

负责小到中尺度的意义地点。

当前已有：古树、泉眼、山脊门、静水湾、石阵。

未来扩展：

1. 村庄地点：羊圈、井、集市、海边、老人屋、占卜帐篷。
2. 沙漠地点：绿洲、残墙、地下古城入口、风蚀石柱、废弃营地。
3. 边界地点：渡口、山口、灯塔、洞穴、旧路标。
4. 地点要有语义标签，供征兆、感知、记事本和 AI 导演查询。

### 5.6 Ecology 层

新增生态与人物行为层。

职责：

1. 动物生成、群体移动、觅食、迁徙、惊扰和回归。
2. NPC 日程、工作、休息、对话和简单关系。
3. 生态事件：鸟群迁飞、羊群走散、鱼群出没、商队经过。
4. 行为可以成为征兆载体，例如飞鸟方向、羊群不安、商人传闻。

初期不追求复杂仿真，优先做少量高辨识行为。

2026-05-12 补充实现：生态系统已按配置控制鸟群/鱼群数量，并通过状态更新间隔和视觉更新间隔分频，避免每帧重算全部行为。

### 5.7 Journey 层

负责长期旅程状态、阶段推进、梦境、玩家意愿和导演接口。

当前已有短旅程状态。未来拆分为：

1. `JourneyState`：保留短期旅程、当前阶段、记忆和回应。
2. `StoryArcState`：新增长期主线，如村庄、梦境、寻找出路、渡河、沙漠、金字塔。
3. `IntentState`：记录玩家行为体现出的意愿，如向海、向山、停留村庄、寻找商人、追随鸟群。
4. `DreamState`：管理梦境触发、梦境内容、醒后回响和反复出现。
5. `DirectorState`：选择下一批候选征兆、地点、NPC 或梦境，但不显示任务目标。

### 5.8 Omen / Sign 层

负责征兆生成、强度、方向、阶段、衰退、回归和表现触发。

未来规则：

1. 征兆来自世界规律，而不是凭空出现。
2. 征兆与玩家意愿相关，意愿越明确，征兆越清晰。
3. 玩家长期无视时，征兆逐渐消退。
4. 玩家重新寻找时，征兆逐渐回归。
5. 感知会临时提高征兆可读性。
6. 征兆表现包括光、风、鸟群、雾、沙暴间隙、星空、声音预留、NPC 话语和地标轮廓。

### 5.9 Perception 层

新增主动感知系统。

职责：

1. 接收玩家主动输入。
2. 判断是否有足够意愿、平静度或情境条件。
3. 请求征兆系统增强表现。
4. 记录感知结果到记事本。
5. 失败时给出自然反馈，例如风声散去、鸟群沉默，而不是 UI 报错。

### 5.10 Notebook 层

新增记事本系统，替代任务栏。

职责：

1. 自动记录梦境。
2. 自动记录重要对话。
3. 自动记录抵达地点和世界回应。
4. 自动记录玩家观察到的征兆。
5. 支持后续玩家手写笔记。
6. 支持按“梦境、人物、地点、征兆、旅程回响”浏览。

禁止：

1. 不显示待办任务。
2. 不显示任务完成百分比。
3. 不显示奖励清单。
4. 不把 AI 建议直接翻译成命令。

### 5.11 UI 层

负责主菜单、暂停、正式 HUD、开发 HUD、记事本、小地图、临时物品栏和设置。

设计要求：

1. 正式 HUD 默认极简。
2. 开发 HUD 可开关，显示坐标、共鸣、平静、距离等调试信息。
3. 小地图只帮助空间理解，不画任务路线。
4. 地点方向指引要像自然方位或记忆标记，不像任务箭头。
5. 快速移动只对已抵达、已理解且叙事允许的地点开放。
6. 物品栏默认不存在，只在造船、特殊哲学物品或临时流程中出现。

### 5.12 Camera / Player 层

负责第一人称、第三人称、移动、跳跃、交互和视角切换。

设计要求：

1. 第一人称继续作为沉浸探索主模式。
2. 第三人称要支持旅行、观察角色、过渡动画和展示模式。
3. 两种视角共享同一个玩家身体和交互状态。
4. 第三人称先用占位角色和程序化动画，不等待完整美术。

2026-05-12 补充实现：第三人称镜头距离、高度、侧向偏移、平滑和地面净空已配置化；角色占位具备站立、行走、奔跑、跳跃四类基础动画状态枚举，供后续视觉动画接入。

### 5.13 Interaction 层

负责轻交互、对话、临时物品和环境动作。

优先级：

1. 靠近、停留、注视、聆听。
2. 与 NPC 对话。
3. 与动物轻互动。
4. 读写记事本。
5. 造船、渡河、开门等地图边界动作。
6. 战斗暂不作为核心优先级。

### 5.14 AI Director 层

负责未来 AI 个性化历险接入。

接口原则：

1. AI 只提出候选，不直接控制世界。
2. 所有候选必须经过世界规则验证。
3. AI 失败时使用硬编码导演回退。
4. AI 输出要结构化，避免直接把大段文本塞进游戏逻辑。
5. 记录输入、输出、采纳结果和回退原因，便于调试。

### 5.15 Presentation 层

负责每个阶段的可重复展示。

要求：

1. 每个大系统必须有展示模式覆盖。
2. 展示不依赖随机碰撞，必须可重复播放。
3. 新增系统先进入展示模式，再接入正式探索。
4. 未来展示分组：村庄开篇、梦境与感知、多地图边界、沙漠金字塔、生态行为、第三人称。

## 6. 阶段开发路线

### 阶段一：村庄开篇与梦境

目标：让玩家从村庄出生，而不是直接出现在野外。玩家可以停留生活，也会在数日后梦见远方金字塔。

核心交付：

1. 程序化村庄出生区。
2. 羊群、牧羊人、商人、海边和基础日程。
3. 梦境系统第一版。
4. 梦境后征兆开始出现。
5. 展示模式覆盖村庄和梦境。

### 阶段二：意愿与感知

目标：玩家行为能积累意愿，主动感知能让征兆更清晰。

核心交付：

1. 意愿记录。
2. 感知输入。
3. 感知表现增强。
4. 征兆增强、消退、回归规则。
5. 感知展示场景。

### 阶段三：记事本与正式 UI

目标：用记事本替代任务栏，用极简正式 HUD 替代调试面板。

核心交付：

1. 记事本入口。
2. 梦境、对话、地点、征兆自动记录。
3. 正式 HUD 与开发 HUD 分离。
4. 小地图/方位感第一版。
5. 临时物品栏规则文档和占位入口。

### 阶段四：多地图与自然边界

目标：让世界从单张连续地形升级为多区域世界，并通过河流、山脉、海洋等自然边界过渡。

核心交付：

1. `WorldRegion` 和 `RegionGraph`。
2. 村庄区域、边界区域、沙漠区域第一版。
3. 迷雾河或山口过渡。
4. 区域加载/卸载。
5. 地图切换展示。

### 阶段五：沙漠、沙暴与金字塔

目标：实现第一张强吸引力远方地图：沙漠中沙暴遮掩的巨大金字塔。

核心交付：

1. 沙漠群系。
2. 沙尘暴天气。
3. 巨大金字塔地标。
4. 绿洲、戈壁、地下古城入口。
5. 梦境、征兆和地标绑定。

### 阶段六：生态与人物行为

目标：让自然世界和村庄人物开始“自己运行”。

核心交付：

1. 轻量行为树。
2. 羊群、鸟群、鱼群第一版。
3. 牧羊人、商人、占卜人日程。
4. 对话记录进入记事本。
5. 生态征兆：飞鸟方向、动物异常、商人传闻。

### 阶段七：第三人称与角色存在感

目标：支持第一人称和第三人称主视角游玩。

核心交付：

1. 视角切换状态。
2. 第三人称镜头。
3. 占位角色模型与程序化动画。
4. 镜头避障。
5. 展示模式覆盖双视角。

### 阶段八：AI 个性化导演

目标：在确定性系统稳定后接入 AI，让每个人的历险产生差异。

核心交付：

1. 结构化导演接口。
2. 硬编码导演与 AI 导演共用协议。
3. AI 生成梦境、对话、征兆文本或地点语义建议。
4. 世界规则校验。
5. 离线回退和可回放日志。

## 7. 当前最高优先级

当前最高优先级不再是继续扩展地形技术，也不是直接接入 AI，而是补齐更新后游戏介绍中最核心的开篇体验和主动理解机制：

1. 村庄开篇与梦境。
2. 意愿与感知。
3. 记事本与正式 UI。
4. 多地图与自然边界。
5. 沙漠金字塔地标。

这五项完成后，《道》才会从“有征兆的开放世界原型”进入“符合新介绍的英雄之旅原型”。

## 9. 结论

当前项目已经完成了有价值的底层原型：程序化世界、流式地形、环境视觉、第一人称探索、征兆、意义地点、短旅程和展示模式。更新后的游戏介绍把目标进一步明确为“从村庄出发，经由梦境、意愿、感知、征兆和多地图边界，走向远方地标的英雄之旅”。

后续开发必须围绕这个目标收束：先让玩家在村庄中生活和做梦，再让玩家通过感知理解征兆，随后让世界以自然边界把玩家带向沙漠金字塔。技术系统的优先级应服从这个体验闭环。
