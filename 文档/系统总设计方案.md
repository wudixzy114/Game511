# 《道》系统总设计方案

更新时间：2026-05-13

## 1. 文档目的

本文档用于统一《道》的最终目标、当前阶段目标、系统边界和开发顺序，并明确两件事：

1. 《道》的最终目标没有变，仍然是高质量、程序化生成主导、以世界规律和征兆旅程为核心的开放世界游戏。
2. 当前阶段目标已经收敛，不应再把“所有视觉专项并行铺开”当作第一优先级，而应先完成“探索体验”这一正式可玩竖切。

本文档重点回答：

1. 《道》最终要成为什么。
2. 当前项目已经具备什么。
3. 当前真正缺的是什么。
4. 接下来应该按什么顺序推进。

## 2. 当前总体判断

### 2.1 最终目标不变

《道》不是传统任务驱动开放世界，也不是靠数值、装备和刷取构成循环的游戏。它的核心体验仍然是：

1. 玩家在一个有规律的世界里生活、停留、注视、迷失、感知。
2. 世界通过自然现象、动物行为、人物传闻、天气变化、梦境回响和远方地标给予征兆。
3. 玩家逐渐理解自己的真实意愿，并主动走向内心要去的地方。
4. 最终宝藏不是奖杯，而是旅程本身和返回出发点时的理解。

### 2.2 当前阶段目标已经收敛为“探索优先”

新版《游戏介绍》明确了一点：当前优先级不是同时铺满战斗、城镇、沙漠、AI 个性化导演和全部高质量视觉专项，而是先把“探索”这一核心体验做成正式竖切。

当前阶段的正式验收应当是：

1. 玩家以前 10 分钟的自然规律体验进入世界，而不是被系统任务拉着走。
2. 玩家明确感受到自己是牧羊人，而不是一个抽象测试角色。
3. 梦境、征兆、感知、记事本能够共同驱动玩家离开村庄。
4. 第一张区域边界必须是可理解、可穿越的世界过程，而不是简单传送。
5. 画面继续保持程序化高质量路线，但所有表现优先服务这个探索竖切。

### 2.3 当前项目已经成立的能力

当前项目已经不是空工程，也不是只有几个散乱 demo。代码侧已经具备：

1. 程序化地形、流式加载、LOD、缓存、碰撞代理和地貌采样底座。
2. 村庄开篇、梦境推进、意愿采样、主动感知、征兆反馈和记事本系统。
3. 多区域图结构、迷雾渡口、山口、港口、金字塔地标和区域入口骨架。
4. 羊群、鸟群、鱼群、商人、牧羊人、占卜人等生态与人物原型。
5. 第一/第三人称、展示模式、日志报告、性能报告和硬编码导演接口。
6. 程序化资产注册、蓝图工厂、语义标签和近中远 LOD 的第一版能力。

### 2.4 当前主要需求不一致

结合新版《游戏介绍》和代码现状，当前主要不一致点是：

1. 文档和任务清单之前过度强调“程序化 3A 视觉专项并行推进”，但新版愿景明确当前阶段应先满足探索体验。
2. `JourneyState` 当前只正式覆盖“村庄生活 -> 梦境将至 -> 入梦 -> 梦后回响”，尚未覆盖“渡河/港口 -> 城镇准备 -> 损失分流 -> 沙漠同行 -> 沙漠磨砺”。
3. `RegionGraphState` 已有区域入口与开门条件，但还没有真正的穿越动作闭环，只是入口状态骨架。
4. 村庄里已经有牧羊人、羊圈和羊群，但“牧羊人身份”还主要停留在场景和对话层，没有变成玩家开篇玩法。
5. 记事本和方位感已经存在，但新版需求中的“小地图只显示已知地点”和“玩家自己的短笔记”还没有正式落地。
6. 现有沙漠与金字塔系统更接近远期旅程原型，不应继续挤占开篇探索闭环的第一优先级。

### 2.5 本次对齐结论

本次需求对齐后的结论是：

1. 程序化高质量路线不动摇，仍然是正式路线，不是占位方案。
2. 当前里程碑从“全面画面升级”调整为“探索阶段正式竖切”。
3. 天气、村庄、地表、生态、地标、展示等视觉专项，当前都应转为探索竖切的支撑战线。
4. 下一步开发应先补齐“牧羊人开局 + 梦后离村 + 第一条自然边界穿越”。

## 3. 系统总清单

## 3.1 探索主循环与阶段旅程系统

### 目标

建立“观察环境 -> 感知征兆 -> 做出行动 -> 世界反馈 -> 获得新理解”的核心探索循环，并把它扩展成正式旅程阶段。

### 当前状态

第一段循环已经成立，但正式旅程序列还只到梦后回响。

### 已覆盖内容

1. `JourneyStage` 已覆盖到达、被吸引、抵达地点、世界回应和余响沉淀。
2. `StoryArcStage` 已覆盖 `VillageAwakening`、`VillageLife`、`DreamApproaching`、`Dreaming`、`DreamAfterglow`。
3. 梦境已经能够将长期目标指向沙漠金字塔，并与记事本、征兆、导演输入联动。

### 后续余项

1. 将旅程阶段扩展到“离开村庄 -> 通过河流/港口 -> 城镇准备 -> 第一次损失 -> 沙漠同行 -> 沙漠磨砺 -> 金字塔前夜”。
2. 为失败、放弃、绕路和二次机会建立非任务化的分流结构。
3. 让每个阶段都能沉淀到记事本、征兆反馈和区域状态，而不是只改一个剧情枚举。

## 3.2 开篇村庄与牧羊人身份系统

### 目标

让玩家以牧羊人的身份进入世界，并通过羊群、海风、劳作和村庄生活理解“世界规律”。

### 当前状态

村庄空间和角色关系已经建立，但玩家自己的牧羊玩法还没有成立。

### 已覆盖内容

1. 村庄布局、羊圈、水井、集市、海边、村外小路等空间已经存在。
2. 牧羊人、商人、羊群和轻交互记录已经接通。
3. `VillageAtmosphere` 已经统一驱动海雾、风、布棚、炊烟、生活密度和梦后不安。

### 后续余项

1. 把羊群从环境角色升级为开篇玩法对象，至少形成跟随、归圈、饮水、吃草或放牧中的一条正式闭环。
2. 让玩家的牧羊行为参与梦境触发和离村意愿积累，而不是只靠时间推进。
3. 让村庄阶段的见闻被稳定记录到记事本，成为后续回望和自我理解的依据。

## 3.3 世界入口与穿越方式系统

### 目标

让区域切换隐藏在世界理解、行动欲望和实际穿越过程里，而不是变成显式传送门。

### 当前状态

入口骨架已具备，正式穿越玩法尚未形成。

### 已覆盖内容

1. `RegionGraphState` 已建立海边村庄、草地林地、山地边界、沙漠和远海区域。
2. 迷雾渡口、山口、港口三类 `TransitionGate` 已存在，并有 `Hidden`、`Hinted`、`Open`、`Crossed` 状态。
3. 区域入口已经能受梦后状态、意愿和征兆影响。

### 后续余项

1. 选定第一条正式穿越路线，优先实现“迷雾河旧渡口”或“港口小船”之一。
2. 将“入口显现”升级为“线索发现 -> 条件满足 -> 穿越动作 -> 到达对岸/新区域”的完整流程。
3. 后续再补攀爬、航行和更长距离穿越，而不是现在就同时铺开所有方式。

## 3.4 征兆、意愿、感知与记事本系统

### 目标

在不依赖任务栏的前提下，让玩家理解自己为何出发、该看什么、下一步能尝试什么。

### 当前状态

这一组系统是当前项目最成熟的主线底座之一。

### 已覆盖内容

1. 意愿通道、主导意愿、主动感知、征兆共鸣和梦后回响已经打通。
2. 征兆可由光、风、鸟群、人物、梦境和地标轮廓表达。
3. 记事本已能记录梦境、对话、地点和征兆，并支持分类查看和回看。

### 后续余项

1. 将梦后征兆优先收束到新版愿景要求的几类：梦境重复意象、鸟群/风向、星象天象、特定引路人。
2. 让“预兆减弱、消退、重新恢复”的逻辑继续强化，避免玩家感到被任务箭头追赶。
3. 补齐“玩家自己的短笔记”输入能力，使记事本不只记录系统自动摘要。

## 3.5 NPC、动物与世界规律理解系统

### 目标

让劳动者、旅人和动物既是生态成员，也是帮助玩家理解征兆的观察者。

### 当前状态

第一版生态和人物行为已经成立，但还未成为开篇体验的主要驱动力。

### 已覆盖内容

1. 羊群、鸟群、鱼群、牧羊人、商人、占卜人的行为与调度已经存在。
2. 商人传闻、占卜人灯火、羊群不安等生态信号已能联动梦后状态与离村意愿。
3. 生态角色已经接入程序化资产体系和基础表演结构。

### 后续余项

1. 优先把“牧羊人、商人、占卜人、鸟群”做成开篇探索的正式征兆载体。
2. 让 NPC 更明确地根据天气、危险和阶段变化改变行为，而不是只做轮转展示。
3. 再逐步扩展到更远期的城镇居民、沙漠同行者和更复杂的社会行为。

## 3.6 地标巨构与远方奇观系统

### 目标

让远方地标承担愿望的形体，但不提前压过开篇探索竖切。

### 当前状态

沙漠金字塔已经有较强原型，但它当前属于中后段旅程支撑系统。

### 已覆盖内容

1. 金字塔、绿洲、残墙、遗物和沙暴显隐逻辑已经存在。
2. 金字塔可见性已与梦后状态、感知和征兆强度联动。
3. 展示模式已能输出沙暴远见金字塔等样张基线。

### 后续余项

1. 当前先保持地标系统可运行，不再让其抢占开篇牧羊与渡河任务的优先级。
2. 当第一道边界穿越完成后，再继续推进城镇后段与沙漠奇观的震撼度升级。
3. 后续再把地下入口、废墟节奏、动物痕迹和金字塔近景构造做深。

## 3.7 程序化资产与高质量视觉路线

### 目标

把程序化生成持续建设成正式视觉语言，同时明确它服务当前可玩目标，而不是脱离玩法独自推进。

### 当前状态

正式路线已经纠偏成功，但资产和材质质量仍处于第一阶段。

### 已覆盖内容

1. 程序化资产注册表、蓝图工厂、语义标签和 LOD 基础结构已经形成。
2. 村庄、生态、边界、地标等关键对象都已有程序化类型与配方路径。
3. 环境快照、统一风场和村庄氛围层已经为视觉统一收口打下底座。

### 后续余项

1. 所有视觉专项都应先服务“开篇牧羊、梦后离村、边界穿越、对岸入口”这四类场景。
2. 再继续深化构型层、材质层、动画层、LOD 层和展示层。
3. 不允许因为当前阶段强调探索体验，就退回外部高模接管或低质量玩具化几何。

## 3.8 UI 与辅助系统

### 目标

保持极简 UI，但提供足够的理解辅助，让玩家不迷失于交互层面。

### 当前状态

已有记事本、方位感、回看和形式化 HUD；新版愿景中的部分辅助还缺失。

### 已覆盖内容

1. 正式 HUD 与开发 HUD 已分离。
2. 记事本、方位感、回程提示、征兆文本、交互提示已经存在。
3. 当前系统已经避免任务清单式语言和目标箭头。

### 后续余项

1. 补齐新版需求中的“小地图只显示地形和已知地点”的正式实现。
2. 强化重要对话回看、最近征兆和地点发现的可读性。
3. 继续压制显式任务语言，所有辅助仍应保持非命令式。

## 3.9 展示、截图与性能验收系统

### 目标

让当前探索竖切和后续视觉升级都能稳定展示、稳定截图、稳定复盘。

### 当前状态

基础能力已存在，但与新版阶段目标还没有完全对齐。

### 已覆盖内容

1. 日志、性能报告和展示模式已经建立。
2. 六个视觉样张基线已经存在。
3. 性能统计已覆盖多个核心阶段。

### 后续余项

1. 新增“梦后离村”“边界穿越”“对岸入口”三类正式样张。
2. 继续补截图落盘、配置摘要和前后对照归档。
3. 所有与开篇探索竖切相关的重型改动，都必须继续走截图、日志、性能三重验证。

## 4. 当前开发顺序

现阶段的正式开发顺序应调整为：

1. 第一优先级：开篇牧羊与渡河探索闭环。
2. 第二优先级：城镇准备、第一次损失和非任务化分流结构。
3. 第三优先级：沙漠同行、危险磨砺、关键觉醒和金字塔前夜。
4. 持续并行但不抢主线优先级：程序化资产、天气、村庄、地表、生态、地标和展示验收的高质量支撑升级。

## 5. 结论

《道》当前最重要的不是继续把所有视觉专项同时往前推，而是先把新版愿景中最核心的探索体验做成正式可玩竖切。

接下来必须坚持以下原则：

1. 程序化高质量表现仍然是正式路线，不是过渡路线。
2. 探索竖切是当前第一优先级，视觉专项为其服务。
3. 任何新任务都必须说明它服务的是哪一个旅程阶段，而不是只说明它会让画面更美。
4. 当前阶段完成标准是“玩家愿意离开村庄，并能自然穿越第一道边界”，不是“所有视觉专项同步收尾”。
