# 日志工具使用说明

## 日志文件

日志目录：

```text
logs/
```

每类日志只保留当前和上一次两份：

- `application.log`
- `application.log.1`
- `error.log`
- `error.log.1`
- `performance.log`
- `performance.log.1`

程序每次启动时会先轮转旧日志：

- 当前 `*.log` 移动为 `*.log.1`
- 旧的 `*.log.1` 被删除
- 新运行写入新的 `*.log`

## HTML 查看器

生成日志查看页面：

```powershell
.\scripts\log.ps1
```

默认输出：

```text
logs/log-report.html
```

指定目录或输出：

```powershell
.\scripts\log.ps1 -LogDir .\logs -Output .\logs\log-report.html
```

HTML 页面支持过滤：

- 日志类型：application / error / performance
- 日志级别：ERROR / WARN / INFO / DEBUG / TRACE
- 系统 target：例如 `dao_game::world::streaming`
- 全文搜索：message、fields、target、source

## AI 观测要求

遇到以下任务时，AI 应生成并查看日志 HTML：

- 游戏启动失败或自动退出异常
- 主菜单、状态机、暂停、展示模式、探索模式流程异常
- 资源加载、世界生成、流式加载、碰撞代理、UI 更新异常
- 性能报告中出现异常尖峰或 `low instrumentation coverage`
- 用户要求调查 bug、报错、卡顿或行为不一致

推荐流程：

```powershell
.\scripts\log.ps1
```

然后在 `logs/log-report.html` 中按以下顺序过滤：

1. `ERROR`
2. `WARN`
3. 相关系统 target，例如 `dao_game::world::streaming`
4. 关键词全文搜索

不要只依赖终端最后几行输出判断问题；日志 HTML 会同时展示当前和上一次运行。

## 格式

新日志统一写为 JSON 行，便于工具解析和过滤。旧文本日志仍会作为 raw 行展示，但 target 和字段过滤能力会弱一些。
