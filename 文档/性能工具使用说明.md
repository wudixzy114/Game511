# 性能工具使用说明

## 主要命令

日常只需要一个入口：

```powershell
.\scripts\perf.ps1
```

默认行为：

- 自动跳过主菜单，进入 `presentation` 展示模式。
- 运行 12 秒后自动退出。
- 使用日志系统的轮转文件生成 `logs/performance-report.html`。
- 不再额外复制性能日志快照，避免重复文件。

性能日志只保留：

```text
logs/performance.log
logs/performance.log.1
```

其中：

- `performance.log`：本次运行
- `performance.log.1`：上一次运行

## AI 必须遵守的性能优化流程

只要任务涉及性能优化，AI 必须执行：

1. 优化前采集 baseline：

```powershell
.\scripts\perf.ps1 -Seconds 12
```

2. 修改代码。

3. 优化后再次采集：

```powershell
.\scripts\perf.ps1 -Seconds 12
```

4. 运行对比：

```powershell
.\scripts\perf.ps1 -Action compare
```

5. 最终回复必须汇报对比结果，包括：

- 平均帧耗时变化
- p95 / p99 变化
- 超预算帧数变化
- 主要瓶颈阶段变化
- 是否出现 `low instrumentation coverage`

如果数据没有改善，必须明确说明“本次优化未被性能数据验证有效”，并给出下一步建议。

## 常用选项

```powershell
.\scripts\perf.ps1 -Seconds 20
.\scripts\perf.ps1 -Mode exploration
.\scripts\perf.ps1 -Output .\logs\my-report.html
```

只采集并打印报告：

```powershell
.\scripts\perf.ps1 -Action capture -Seconds 10
```

查看当前日志：

```powershell
.\scripts\perf.ps1 -Action report
```

对比当前和上一次：

```powershell
.\scripts\perf.ps1 -Action compare
```

只生成 HTML：

```powershell
.\scripts\perf.ps1 -Action html
```

对比指定两个日志：

```powershell
.\scripts\perf.ps1 -Action compare -Baseline .\logs\old.log -Candidate .\logs\new.log
```

输出 JSON：

```powershell
.\scripts\perf.ps1 -Action report -Json
```

## 瓶颈诊断能力

报告会输出 `bottlenecks` / `candidate_bottlenecks`，用于回答“瓶颈在哪里”：

- 帧预算问题：p95 是否超过 `frame_time_budget_ms`。
- 尖峰问题：p99 和 p50 差距是否过大。
- 主热点阶段：哪个阶段占据最多已埋点耗时。
- 尖峰阶段：哪个阶段 p99 明显高于平均值。
- 埋点覆盖率：已埋点阶段能解释多少平均帧时间。

如果报告提示 `low instrumentation coverage`，说明真实瓶颈可能在未埋点区域，需要继续给渲染准备、资源加载、启动流程或新系统补充埋点。

## 配置

`config/app.toml`：

```toml
performance_detail_interval = 1
frame_log_interval = 120
```

含义：

- `performance_detail_interval = 1`：每帧记录细粒度样本，适合性能分析。
- `performance_detail_interval = 0`：关闭逐帧细节样本。
- `frame_log_interval`：普通帧日志输出间隔，不影响细粒度 HTML 报告。
