# 任务清单 2026-05-12 - 视觉展示与性能验收管线

## 最终目标

1. 建立“画面改动必须可展示、可截图、可回放、可性能对比”的验收流程。
2. 避免视觉迭代只凭终端输出或主观印象判断。
3. 让 3A 方向的追求变成一批可持续通过的质量门槛。

## 展示与截图

### 1. 展示场景矩阵

- [ ] 展示模式新增固定矩阵：村庄黎明、梦后村外、迷雾边界、沙暴金字塔、绿洲废墟、夜空海边。
- [ ] 每个展示场景记录场景名、相机参数、天气、时间、玩家位置和预期视觉重点。
- [ ] 展示镜头必须覆盖第一人称和第三人称。
- [ ] 展示场景不能依赖玩家手动操作才能看到关键效果。

### 2. 截图检查流程

- [ ] 建立截图输出目录规则，按日期和场景保存。
- [ ] 每张截图记录配置摘要和当前 git commit。
- [ ] 为截图写检查清单：地标可见性、UI 遮挡、文字溢出、材质单调、实体穿插、空白画面。
- [ ] 关键改动前后保留对比截图。

## 性能验收

### 1. 性能基准

- [ ] 为视觉展示矩阵建立 baseline 性能日志。
- [ ] 新增资产、粒子、植被、天气后必须运行 `.\scripts\perf.ps1`。
- [ ] 优化后运行 `.\scripts\perf.ps1 -Action compare`。
- [ ] 性能结论必须说明平均帧耗时、p95、p99、超预算帧和主要瓶颈阶段。

### 2. 质量门槛

- [ ] 所有新增重型视觉系统接入 `FramePerformance`。
- [ ] 如果性能报告提示埋点覆盖不足，先补埋点再下结论。
- [ ] 视觉质量回退选项必须配置化：粒子密度、植被密度、细节距离、阴影或雾强度。
- [ ] 不能为了性能完全移除关键地标或核心征兆表现，应优先降级 LOD。

## 任务额外说明

1. 展示与性能管线是所有视觉任务的共同验收入口。
2. 文档、截图、日志和性能报告要共同判断质量，单独看任何一种都不够。
3. 收尾前通常运行 `cargo fmt --all --check`、`cargo test`、`cargo clippy --all-targets -- -D warnings`。
