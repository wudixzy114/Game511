# 任务清单 2026-05-13 - 3A资产框架与图鉴展列区升级

## 目标

1. 建立一套可长期扩展的 3A 级程序化资产框架，不是只为“树”写特例。
2. 支持并行批量生产：同一时间可分别推进树、岩石、遗迹、村庄道具、水岸物、建筑件，而不会互相卡住。
3. 建立比当前材质/物体展示馆更强的“图鉴式展列区”：可筛选类别、查看 3D 资产、切换材质与 LOD、实时调参数、导出清单和截图。
4. 保持一条严格闭环：定义层 -> profile 层 -> 几何层 -> 材质层 -> 动画/碰撞层 -> 图鉴验收 -> 世界集成 -> 性能验收。

## 当前判断

1. 现有项目已经具备材质库、程序化资产蓝图、风场、物理、日志、性能报告、材质馆和树木样本的基础。
2. 当前主要问题不是“没有程序化能力”，而是框架边界还不够清晰：对象定义、图鉴交互、参数审查、世界接入、导出工具仍然分散。
3. 当前展示馆更像临时审查区，而不是正式资产图鉴系统；它适合看样本，不适合做大规模资产生产验收。
4. 当前资产生产的扩展成本偏高：新增一个物体族仍需要手工接线，缺少一套标准化单文件入口和统一 manifest。

## 核心策略

### 1. 共享核心，单文件扩展

- 每个资产族使用“共享运行时 + 单文件族定义”的结构。
- 共享运行时负责：稳定 seed、通用请求结构、材质槽、LOD、统计、碰撞 recipe、动画 recipe、manifest、图鉴接入。
- 单文件族定义负责：该物体族自己的 profile 字段、几何规则、材质映射、验收规则、golden seeds。
- 目标写法：
  `src/game/objects/families/tree.rs`
  `src/game/objects/families/rock.rs`
  `src/game/objects/families/ruin_fragment.rs`
  `src/game/objects/families/village_prop.rs`

### 2. 参数驱动，不写散装随机数

- 所有随机变化先进入 profile，再从 profile 生成几何和部件。
- profile 必须可序列化、可导出、可测试、可回放。
- 几何层不直接自己掷随机数，避免“同 seed 不稳定”和后续无法比对。

### 3. 图鉴优先于世界

- 任何新物体族必须先进入图鉴展列区，不直接先散进世界。
- 图鉴中必须支持：
  类别切换、seed 翻页、参数面板、LOD 切换、材质状态切换、风力切换、导出 manifest、截图、验收状态记录。
- 只有图鉴通过验收的族，才允许接进开放世界。

### 4. 并行生产协议

- 并行不是让多人同时乱改核心，而是“核心收敛 + 族文件分治”。
- 每个资产族都遵守同一协议：
  `build_profile(request) -> build_parts(profile, lod) -> build_collision(profile) -> build_manifest(profile)`
- 这样树、岩石、遗迹、村庄道具可以并行推进，只共享底层类型，不共享具体规则实现。

## 单文件并行规范

1. 每个资产族一个主文件，里面至少包含：
   `Profile`
   `build_profile`
   `build_parts`
   `build_collision`
   `approval`
   `golden_seeds`
2. 每个资产族最多再带一个可选 companion 文件：
   `*_tests.rs` 或 `*_presets.rs`
3. 共享逻辑不允许复制进族文件，统一留在核心层。
4. 新增资产族时，先做图鉴，再做世界，不允许直接跳过验收。
