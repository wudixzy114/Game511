# 《道》任务清单：多地图与自然边界（2026-05-12）

## 最终目标

1. 将当前单张连续开放世界升级为多区域世界架构。
2. 通过河流、迷雾、高山、海洋、渡口、山口等自然边界连接地图。
3. 避免玩家从一张地图直接看穿到另一张地图。
4. 为村庄到沙漠、山后地图、远海小岛等后续旅程打底。

## 主要任务1

### 1. 世界架构设计

- [ ] 使用 UTF-8 阅读 `文档/游戏介绍.md` 中“地图”部分。
- [ ] 阅读 `src/game/world.rs`，梳理当前 `WorldMap`、分块、LOD、碰撞代理和展示锚点。
- [ ] 设计 `WorldRegion` 数据结构，包含区域 id、类型、种子、半径、地形配置、地标、边界。
- [ ] 设计 `RegionGraph`，描述区域之间的连接关系。
- [ ] 设计 `TransitionGate`，描述迷雾河、山口、港口、洞穴等自然过渡点。
- [ ] 明确当前 `WorldMap` 如何作为单区域地形采样器被复用。
- [ ] 将设计结果同步到系统设计或子设计文档。

### 2. 区域类型第一版

- [ ] 定义区域类型：村庄海岸、草原/林地、山地边界、沙漠、远海。
- [ ] 每个区域类型定义基础群系倾向、天气倾向、危险倾向、资源倾向和地标需求。
- [ ] 第一版至少实现村庄海岸、山地边界、沙漠三个区域定义。
- [ ] 区域生成必须由种子驱动，可重复。
- [ ] 为区域选择和连接图生成补充单元测试。

## 主要任务2

### 1. 自然边界实现

- [ ] 实现迷雾河边界原型。
- [ ] 实现山脉或山口边界原型。
- [ ] 实现海岸/远海边界原型。
- [ ] 边界应在视觉上自然，不像空气墙。
- [ ] 第一版可以阻挡玩家，但必须提供可被征兆或后续能力解释的通过条件。
- [ ] 边界状态写入日志，便于调试玩家为何无法通过。

### 2. 过渡条件

- [ ] 定义过渡条件类型：找到渡口、造船、翻越山口、跟随 NPC、完成梦后意愿。
- [ ] 第一版至少实现一个可通过边界，例如迷雾河渡口或山口。
- [ ] 过渡条件不显示任务清单，只通过记事本和征兆暗示。
- [ ] 过渡前保存当前区域旅程状态。
- [ ] 过渡后加载目标区域并放置玩家到合理入口。
- [ ] 为过渡条件判定补充单元测试。

## 主要任务3

### 1. 区域流式加载

- [ ] 抽象当前世界生成入口，使其能根据当前区域配置生成地形。
- [ ] 区域切换时清理当前区域实体：地形、地点、NPC、动物、天气特效。
- [ ] 区域切换时保留全局状态：长期旅程、记事本、梦境、玩家已知地点。
- [ ] 区域切换时重建碰撞代理和流式缓存。
- [ ] 区域切换期间避免明显卡死，必要时使用过渡遮罩、梦境、迷雾或加载状态。
- [ ] 切换流程写入日志。

### 2. 视觉遮挡与新鲜感

- [ ] 使用山脉、雾、海平线、天气和距离控制避免看穿下一张地图。
- [ ] 远景 impostor 需要按区域边界裁剪或替换。
- [ ] 沙漠金字塔可在梦境或沙暴间隙中出现，但不应从村庄直接完整可见。
- [ ] 边界附近的天气和地貌需要自然过渡。
- [ ] 为边界可见性建立展示场景。

## 主要任务4

### 1. 征兆、感知和记事本衔接

- [ ] 当玩家在边界附近停留，记录过渡意愿。
- [ ] 感知可强化边界通过线索，例如雾中渡口、山口风声、远海灯光。
- [ ] 记事本记录已发现的边界和传闻，但不写待办。
- [ ] NPC 可提供非任务化传闻，例如“雾散时有人见过旧渡口”。
- [ ] 区域切换后旅程导演更新候选地点和征兆。

### 2. 展示模式

- [ ] 新增“多地图与自然边界展示”。
- [ ] 展示覆盖：当前区域、自然边界、感知线索、通过边界、目标区域出现。
- [ ] 展示可重复，不依赖随机玩家行为。

## 主要任务5

### 1. 验证与性能

- [ ] 运行 `cargo fmt --all --check`。
- [ ] 运行 `cargo test`。
- [ ] 运行 `cargo clippy --all-targets -- -D warnings`。
- [ ] 运行探索模式自动退出验证。
- [ ] 运行展示模式自动退出验证。
- [ ] 如果区域切换或流式加载影响性能，按 `AI开发流程.md` 执行性能 baseline、优化后采样和 compare。

## 任务额外说明

多地图不是简单传送，也不是关卡列表。边界必须是世界的一部分，玩家应感觉自己通过了河、山、雾、海，而不是点击了菜单。
