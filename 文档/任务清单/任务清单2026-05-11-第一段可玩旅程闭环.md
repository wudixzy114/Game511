# 《道》任务清单：第一段可玩旅程闭环（2026-05-11）

## 最终目标

1. 让玩家在没有传统任务面板的情况下，完成一段短小但完整的“被世界征兆牵引”的体验。
2. 建立确定性的旅程导演接口，为后续 AI 个性化历险保留接入点。
3. 将程序化地点、征兆反馈、轻交互、世界回应和旅程记忆串成一个可运行闭环。

## 主要任务1

### 1. 设计确认

- [x] 使用 UTF-8 阅读 `文档/游戏介绍.md`。
- [x] 阅读 `AI开发流程.md`、`文档/质量要求.md`、`文档/效果展示要求文档.md`。
- [x] 对照现有源码和已完成任务，确认当前项目已经具备世界、环境、征兆、第一人称、展示模式和 UI 生命周期底座。
- [x] 更新 `文档/系统总设计方案.md`，将下一阶段确定为“第一段可玩旅程闭环”。

### 2. 旅程核心系统

- [x] 新增 `src/game/journey.rs` 和 `JourneyPlugin`。
- [x] 定义 `JourneyState`，记录当前旅程阶段、选中的意义地点、已触发征兆和旅程记忆。
- [x] 定义 `JourneyStage`，至少覆盖：初入世界、征兆浮现、被牵引、抵达地点、世界回应、回响沉淀。
- [x] 将旅程状态接入 `AppScreen::InGame` 生命周期，进入游戏初始化，返回主菜单清理。
- [x] 为阶段推进逻辑补充单元测试，确保同样输入下结果可回放。

## 主要任务2

### 1. 程序化意义地点

- [ ] 新增 `src/game/places.rs` 或在世界系统内建立清晰的地点子模块。
- [ ] 定义 `MeaningfulPlace`、`PlaceKind` 和地点语义标签。
- [ ] 先实现 3 到 5 类地点原型：古树、泉眼、山脊门、静水湾、石阵。
- [ ] 基于 `WorldMap`、群系、坡度、水位、海拔和出生点距离筛选地点候选。
- [ ] 使用程序化 mesh、材质、光效或散布物组合生成可识别地点轮廓。
- [ ] 地点实体随游戏会话生成和清理，不污染主菜单或展示模式生命周期。
- [ ] 为地点筛选补充确定性测试。

### 2. 征兆引导升级

- [ ] 将当前征兆从单次触发升级为可持续反馈，支持强度、方向、目标地点和冷却。
- [ ] 根据玩家是否接近意义地点，改变征兆表现。
- [ ] 不使用任务箭头和小地图路线，优先使用远景光、风、雾、粒子、天气和漫游体行为暗示方向。
- [ ] 保留调试日志，记录征兆选择原因、目标地点和触发条件。
- [ ] 为征兆选择逻辑补充单元测试。

## 主要任务3

### 1. 轻交互与世界回应

- [ ] 实现地点接近判定。
- [ ] 实现第一版轻交互条件：靠近、停留、注视或聆听。
- [ ] 触发世界回应时，至少联动一种环境变化和一种征兆变化。
- [ ] 世界回应不发放传统奖励，只写入旅程记忆并改变当前体验状态。
- [ ] 确保暂停、重开、返回主菜单时交互状态能正确清理。

### 2. 旅程记忆 UI

- [ ] 将当前 HUD 区分为开发 HUD 和正式体验 HUD。
- [ ] 在暂停界面新增“回响”区域，展示玩家已经经历的地点和征兆。
- [ ] 旅程记忆只记录经历，不显示待办任务。
- [ ] 中文字体沿用当前 `UiFontHandle`，避免 UI 字体回退导致乱码。
- [ ] 为旅程记忆文本格式化补充测试。

## 任务额外说明

本任务不是要做传统任务系统，也不是马上接入在线 AI。当前目标是用确定性规则先证明“无任务面板也能形成方向感”的核心体验。后续 AI 个性化历险应接入旅程导演接口，而不是替代世界规律本身。
