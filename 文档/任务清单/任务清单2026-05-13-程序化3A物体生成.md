# 任务清单 2026-05-13 - 程序化3A物体生成

## 最终目标

1. 建立一条可扩展的程序化物体生产线，覆盖树木、岩石、遗迹碎片、村庄道具、建筑部件、水岸物体、生态物体和可交互物。
2. 每类物体都必须支持稳定种子、随机形态、材质槽、LOD、碰撞、风场/动画、语义标签、展示验收和世界流式集成。
3. 先用“树”做第一条完整样本线：树高、主干倾斜、枝条走势、树冠体量、叶色、风摆、近景碰撞、中远景性能都要可验证。
4. 所有物体进入开放世界前，必须先在展馆中可自由移动检查，不能把未验收的占位资产直接散进地图。

## 当前判断

1. 项目已有 `ProceduralAssetSpec`、材质陈列馆、自由移动展馆相机、`WindField`、正式物理插件、性能日志和展示模式基础。
2. 当前已经有 `ProceduralObjectPlugin` 和 12 棵固定 seed 的程序化树样本，但它们仍属于“展馆样本”，还未正式进入 `ProceduralAssetRegistry` 和开放世界流式系统。
3. 当前树的几何仍以 primitive 组合为主，适合作为生成规则验证，但还未达到最终 3A 近景质量。
4. 展馆按 `E` 导出时会卡顿和闪烁。该问题会影响后续所有物体验收，必须作为程序化物体生产线的前置工具稳定性任务处理。

## 总体架构方案

### 1. 物体定义层

- 每个物体族定义 `ObjectKind`、稳定 seed、语义标签、材质槽、碰撞策略、LOD 策略、动画策略和验收状态。
- 生成入口统一为 `ObjectGenerationRequest`：包含 kind、seed、LOD、生态上下文、材质上下文、展示/世界模式。
- 生成结果统一为 `ObjectGeneratedAsset`：包含 part 列表、材质槽引用、collider recipe、animation binding、统计信息和 manifest 条目。
- 所有 profile 生成必须是纯逻辑函数，支持单元测试和回归对比。

### 2. Profile 与规则层

- 每个物体族先生成 profile，再由 profile 生成 mesh/part，不允许几何代码直接散落随机数。
- profile 需要记录可解释参数，例如树木的高度、树龄、主干半径、倾斜、分枝数量、叶簇密度、健康度、湿度、风柔性。
- 同一 seed 在同一版本规则下必须稳定；规则升级需要记录版本号，避免旧场景回放漂移。
- 支持生态上下文影响 profile：湿地、草甸、山脊、沙漠、村庄、遗迹、水岸、梦境/征兆状态。

### 3. 几何生成层

- 近景：生成真实可检查结构，树木需要主干、分枝、细枝、叶簇、根部、局部阴影或地表接触痕迹。
- 中景：合并同材质部件，降低实体数量，保留轮廓和主要色块。
- 远景：使用批处理、impostor 或 billboards，不把大量近景实体塞进世界流式系统。
- 生成器必须输出统计信息：part 数、mesh 顶点数、材质槽数、collider 数、估算运行成本。

### 4. 材质绑定层

- 物体只引用材质槽，不在生成器内部随意创建散装 `StandardMaterial`。
- 第一阶段树木材质槽：`bark_primary`、`bark_worn_edge`、`leaf_primary`、`leaf_secondary`、`leaf_dry`、`root_shadow`。
- 材质槽需要能绑定到材质陈列馆中的正式程序化材质定义，并记录稳定 ID。
- 支持环境变体：湿润、尘土、风蚀、枯黄、苔藓、雪、水线、遗迹污染、梦境偏色。

### 5. 动画与风场层

- 树木风摆拆成三层：主干低频低幅、枝条中频中幅、叶簇高频 flutter。
- 所有风摆读取统一 `WindField`；展馆没有实时环境时使用稳定默认风。
- 大规模树林必须支持距离降频：近景逐 part 更新，中景按树更新，远景按批次 shader/相位更新。
- 动画不能破坏几何连接：树冠不能脱离枝条，主干不能出现突然折断式旋转。

### 6. 物理与交互层

- 近景树至少生成主干 collider；低枝、根部、岩石、道具按 gameplay 需要生成简化 collider。
- 远景树只保留视觉和生态语义，不进入物理世界。
- 可交互物体需要 sensor：观察、采集、遮挡、征兆感知、区域语义、特殊剧情触发。
- collider 生成要进入 `DaoPhysicsPlugin`，并能在物理调试视图中确认。

### 7. 展馆与验收层

- 每个物体族先进入展馆，有固定 seed 阵列、自由移动检查、光照切换、导出 manifest 和截图。
- 展馆必须支持按物体类别浏览：树木、岩石、遗迹、村庄道具、建筑件、水岸物、生态物。
- 每个样本需要记录验收状态：满意、需要修改、禁用、性能风险、等待材质。
- 展馆导出不能造成明显卡顿或闪烁；导出逻辑必须和实时浏览解耦。

### 8. 世界流式集成层

- 通过 biome/ecology/places 输出物体分布请求，不由 world chunk 内部硬编码物体细节。
- 近景对象使用实体和真实 collider；中远景使用合批 mesh 或 impostor。
- 流式系统需要缓存同 seed 生成结果，避免玩家来回移动时重复生成重型物体。
- 物体生成预算进入性能报告，能看到 generation、upload、animation、collision streaming 的耗时。

## 任务额外说明

1. 程序化物体开发必须先保证展馆审查体验稳定。导出卡顿和闪烁会污染验收判断，优先级高于新增更多样本。
2. “3A 物体”不是指单纯增加数量，而是每个物体族都有形态规则、材质规则、动画规则、LOD、碰撞和验收闭环。
3. 任何进入开放世界的物体族，都必须先完成展馆样本、manifest、基本测试和性能观测。
4. 后续实现时应优先沿用现有 `ProceduralAssetSpec`、`WindField`、`DaoPhysicsPlugin`、材质陈列馆和性能日志，不再并行发明第二套基础设施。
