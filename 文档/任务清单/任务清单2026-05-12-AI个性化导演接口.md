# 《道》任务清单：AI 个性化导演接口（2026-05-12）

## 最终目标

1. 在不依赖在线 AI 的前提下，建立可测试、可回放的旅程导演接口。
2. 让硬编码导演和未来 AI 导演共用同一套输入输出协议。
3. 允许 AI 个性化梦境、对话、征兆文本和地点语义建议。
4. 保证 AI 建议必须经过世界规则校验，不能破坏游戏规律。

## 主要任务1

### 1. 接口边界设计

- [ ] 使用 UTF-8 阅读 `文档/游戏介绍.md` 中 AI 集成和独家历险要求。
- [ ] 阅读 `src/game/journey.rs`、`src/game/signs.rs`、`src/game/places.rs`、`src/game/presentation.rs`。
- [ ] 明确 AI 是上层导演，不是世界模拟本身。
- [ ] 明确在线 AI 不作为当前运行必需依赖。
- [ ] 明确硬编码导演必须始终可用。
- [ ] 设计 `JourneyDirector` 接口草案。

### 2. 导演输入 schema

- [ ] 定义导演输入：玩家位置、当前区域、已知地点、旅程阶段、梦境状态、意愿状态、记事本摘要。
- [ ] 定义可选输入：最近对话、最近征兆、天气、NPC 状态。
- [ ] 输入需要可序列化，便于日志和未来 AI 调用。
- [ ] 输入不能包含不必要的大型世界数据，只传摘要和候选。
- [ ] 为输入构建补充单元测试。

## 主要任务2

### 1. 导演输出 schema

- [ ] 定义导演输出类型：候选征兆、候选梦境、候选对话、候选地点、候选环境回应。
- [ ] 输出必须是建议，不是强制命令。
- [ ] 输出包含语义标签、强度、持续时间、前置条件和回退文案。
- [ ] 输出不能直接生成任务目标。
- [ ] 输出需要经过规则校验才能采纳。
- [ ] 为输出校验补充单元测试。

### 2. 硬编码导演实现

- [ ] 将现有旅程推进中“选择目标、触发征兆、写入记忆”的逻辑逐步整理到硬编码导演。
- [ ] 硬编码导演实现与 AI 导演相同接口。
- [ ] 硬编码导演覆盖村庄梦境、第一段旅程、沙漠金字塔候选。
- [ ] 硬编码导演输出写入日志。
- [ ] 硬编码导演必须在无网络、无密钥情况下正常运行。

## 主要任务3

### 1. 世界规则校验

- [ ] 新增导演建议校验层。
- [ ] 校验地点是否存在或可生成。
- [ ] 校验征兆是否符合当前环境和玩家意愿。
- [ ] 校验梦境或对话是否符合当前旅程阶段。
- [ ] 校验建议不会暴露不该知道的地图信息。
- [ ] 校验失败时回退到硬编码建议。
- [ ] 失败原因写入日志。

### 2. 可回放日志

- [ ] 记录导演输入摘要。
- [ ] 记录导演输出建议。
- [ ] 记录采纳、拒绝或回退原因。
- [ ] 日志避免泄露过多长文本，但保留调试必要信息。
- [ ] 后续日志工具可按 `dao_game::director` target 过滤。

## 主要任务4

### 1. AI 接入预留

- [ ] 预留 AI provider 配置，不在默认路径强制启用。
- [ ] 预留异步请求或后台任务边界，避免阻塞帧循环。
- [ ] 预留超时和失败回退策略。
- [ ] 预留结构化响应解析。
- [ ] 预留内容过滤和长度限制。
- [ ] 文档说明 AI 功能默认关闭。

### 2. 展示与验证

- [ ] 新增“导演接口展示”或日志验证场景。
- [ ] 展示硬编码导演根据相同输入给出稳定建议。
- [ ] 展示校验拒绝不合规则建议并回退。
- [ ] 运行 `cargo fmt --all --check`。
- [ ] 运行 `cargo test`。
- [ ] 运行 `cargo clippy --all-targets -- -D warnings`。
- [ ] 运行探索模式和展示模式自动退出验证。

## 任务额外说明

AI 个性化只能建立在确定性系统之上。当前阶段的重点是接口、schema、校验和回退，不是急着联网生成内容。
