# 开发工具使用说明

## 1. 目的

本文档说明当前项目中已经配置好的开发工具、质量工具和文档整理规则，便于后续持续开发时直接复用。

## 2. 运行项目

### 2.1 推荐方式

在项目根目录执行：

```powershell
.\scripts\run-dev.ps1
```

作用：

- 自动确保 `logs/` 目录存在
- 启动当前 Bevy 游戏原型
- 默认进入第一人称探索模式

### 2.2 直接运行

```powershell
cargo run
```

默认会进入第一人称探索模式。

### 2.3 运行展示场景

如果要直接查看当前阶段的展示场景，执行：

```powershell
.\scripts\run-presentation.ps1
```

作用：

- 强制开启 `DAO_PRESENTATION_MODE`
- 进入可重复播放的展示模式
- 自动编排世界、昼夜和征兆展示流程

### 2.4 第一人称操作

默认探索模式下的操作：

- `W` `A` `S` `D`：移动
- `Shift`：冲刺
- `Space`：跳跃
- 鼠标移动：转动视角
- `Esc`：释放鼠标
- 鼠标左键：重新锁定鼠标

## 3. 质量检查工具

### 3.1 一键检查

在项目根目录执行：

```powershell
.\scripts\dev-check.ps1
```

该脚本会依次执行：

- `cargo fmt --all --check`
- `cargo check`
- `cargo test`
- `cargo clippy --all-targets -- -D warnings`

### 3.2 单独执行

如果只想检查某一项，可以分别运行：

```powershell
cargo fmt --all --check
cargo check
cargo test
cargo clippy --all-targets -- -D warnings
```

说明：

- 当前项目已配置“告警即错误”
- 如果 `clippy` 或编译器有告警，检查会直接失败

## 4. 启动烟雾测试

如果只想验证程序是否能够成功启动，而不想一直停留在窗口中，可以执行：

```powershell
$env:DAO_AUTO_EXIT_SECONDS='0.5'
cargo run
```

说明：

- 该环境变量表示程序启动后自动在指定秒数后退出
- 适合做快速启动验证
- 正常开发时不需要设置这个变量

## 5. 配置文件

主配置文件位于：

```text
config/app.toml
```

当前主要配置项包括：

- `window_title`：窗口标题
- `log_directory`：日志目录
- `performance_log_name`：性能日志文件名
- `frame_log_interval`：性能采样写日志的帧间隔
- `[presentation]`：展示模式开关、单场景时长、镜头过渡速度
- `[world]`：世界种子、世界半径、分块半径、可见分块半径、展示锚点搜索半径、每帧流式分块生成预算、流式分块缓存容量、单元尺寸、网格细分、地形尺度、高低起伏、水位、噪声层数、山脊锐度、岸线混合参数、河流频率、河道深度、侵蚀强度、沉积偏置、材质贴图分辨率
- `[environment]`：昼夜循环时长、漫游半径、漫游速度
- `[player]`：行走速度、冲刺倍率、鼠标灵敏度、视角高度、身体高度、跳跃速度、重力
- `[signs]`：征兆系统阈值与恢复速度
- `[quality]`：目标帧率与单帧预算

修改配置后，重新运行项目即可生效。

## 6. 日志系统

日志目录位于：

```text
logs/
```

当前会生成以下日志：

- `application.log.*`：常规运行日志
- `error.log`：错误级日志
- `performance.log`：性能采样日志

用途建议：

- 调试运行流程时看 `application.log.*`
- 调查错误时优先看 `error.log`
- 观察帧时间和预算超限时看 `performance.log`

## 7. 性能检测

当前已经接入逐帧性能采样系统。

行为规则：

- 按 `frame_log_interval` 定期记录帧时间
- 当单帧耗时超过 `frame_time_budget_ms` 时记录告警
- 相关信息会写入性能日志

这套机制适合后续给各模块继续补充更细的性能埋点。

## 8. 测试系统

当前已为以下基础模块提供测试：

- 配置加载
- 日志辅助逻辑
- 性能采样逻辑
- 展示模式编排逻辑
- 程序化世界采样、河流/侵蚀场与连续分块网格构建
- 征兆状态默认值

运行方式：

```powershell
cargo test
```

## 9. 任务清单管理规则

从现在开始，任务清单按完成状态分目录存放：

- 未完成的任务清单放在 `文档/任务清单/`
- 已完成的任务清单放在 `文档/已经完成的任务文件/`

本次我已经按这个规则整理：

- 原来的 `文档/任务清单.md` 已移动到 `文档/任务清单/道项目任务清单.md`

后续新增任务清单时，也请继续遵循这条规则，避免完成和未完成任务混在一起。

## 10. 建议使用顺序

日常开发建议按下面顺序使用：

1. 先修改代码或配置
2. 用 `.\scripts\run-dev.ps1` 启动查看效果
3. 如有问题先检查 `logs/`
4. 提交前执行 `.\scripts\dev-check.ps1`
5. 根据任务状态，把任务清单放到正确目录
